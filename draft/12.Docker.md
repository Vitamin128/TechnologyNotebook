## 一、Docker 基础与容器日常管理【P0：最高频】

- [ ] Docker 的作用
  - 理解 Docker 如何统一应用及依赖的运行环境，减少本地、测试与部署环境差异。
- [ ] 镜像与容器
  - 区分用于创建容器的镜像与实际运行的容器实例。
- [ ] Docker 客户端与 Engine
  - 理解命令由客户端发出、容器由目标 Docker Engine 管理。
- [ ] 宿主机与容器
  - 区分两者的进程、网络、文件系统和运行环境。
- [ ] 查看容器
  - 查询运行中及已停止的容器，识别名称、状态、镜像和端口。
- [ ] 创建与启动容器
  - 区分从镜像创建新容器与启动已有容器，避免重复创建。
- [ ] 停止与重启容器
  - 理解停止、启动和重启的影响，以及重启不会自动应用所有配置修改。
- [ ] 删除与重建容器
  - 理解容器可被替换，数据保留情况取决于实际存储位置。
- [ ] 容器启动参数
  - 掌握后台运行、命名、端口、环境变量、挂载和网络等常用配置。
- [ ] 容器主进程
  - 理解主进程结束通常意味着容器退出，后台运行不等于程序永久存活。
- [ ] 进入容器执行操作
  - 区分在运行容器中执行新进程与连接已有进程的输入输出。
- [ ] Docker Desktop 基础操作
  - 使用界面查看容器、日志、镜像和卷，并理解它们与命令行管理的是同一套资源。

## 二、日志查看与日常故障排查【P0：最高频】

- [ ] 查看应用日志
  - 查看 Spring Boot 启动信息、异常堆栈和业务日志。
- [ ] 实时跟踪与日志筛选
  - 按时间和行数查看日志，减少大量历史输出造成的干扰。
- [ ] 容器运行状态
  - 区分运行、退出、重启中和不健康等状态。
- [ ] 退出原因与退出码
  - 结合容器状态、日志和退出信息定位失败原因，不只根据退出码下结论。
- [ ] 查看实际容器配置
  - 检查生效的环境变量、启动参数、挂载、网络和资源限制。
- [ ] Spring Boot 启动失败
  - 排查配置缺失、数据库连接失败、端口冲突和 Bean 初始化异常。
- [ ] 容器启动后立即退出
  - 检查主进程、启动方式、文件路径、权限和程序异常。
- [ ] 容器反复重启
  - 区分应用持续失败与重启策略造成的循环。
- [ ] 应用运行但无法访问
  - 依次检查监听地址、容器端口、端口发布、网络和宿主机防火墙。
- [ ] 文件与权限问题
  - 检查 JAR、配置文件、上传目录和日志目录是否存在并可访问。
- [ ] 镜像缺少排查工具
  - 理解精简镜像可能没有 Shell、curl 或 JDK 工具，选择合适的诊断方式。

## 三、使用 Docker 搭建 Spring Boot 依赖环境【P0：最高频】

- [ ] 本地 Java 与容器依赖
  - 在 IDEA 中运行 Spring Boot，通过 Docker 提供数据库、缓存和消息服务。
- [ ] MySQL / PostgreSQL
  - 配置数据库版本、账号、初始化信息和持久化位置，供 Spring 数据源连接。
- [ ] Redis
  - 配置连接地址、认证和持久化方式，供 Spring 缓存或 Redis 客户端使用。
- [ ] 消息队列
  - 根据项目需要启动 RocketMQ、RabbitMQ 或 Kafka，区分服务端配置与客户端配置。
- [ ] RocketMQ 接入地址
  - 根据 Remoting 或 gRPC 客户端确认所需组件，以及 Broker 或 Proxy 地址的可达性。
- [ ] 其他基础设施
  - 按项目需要配置 Nacos、Elasticsearch、MinIO 等服务，确认版本与客户端兼容性。
- [ ] 依赖服务初始化
  - 理解数据库建库、建表和初始化脚本的触发条件，避免误以为每次启动都会执行。
- [ ] 依赖服务就绪
  - 在 Java 应用启动前确认数据库或消息服务可用，区分进程启动与服务可连接。
- [ ] 测试数据保留
  - 为数据库等服务配置持久化，确认重建容器后的数据行为。
- [ ] 团队开发环境复用
  - 使用版本化配置统一依赖版本与启动方式，保留个人环境差异。

## 四、端口、网络与服务连接【P0：最高频】

- [ ] 宿主机端口与容器端口
  - 理解两层端口的用途，区分应用监听端口与外部访问端口。
- [ ] 端口发布
  - 将容器服务映射到宿主机，检查地址、端口和协议。
- [ ] EXPOSE 与端口发布
  - 理解 EXPOSE 记录端口信息，本身不会将服务发布到宿主机。
- [ ] 容器中的 localhost
  - 理解 localhost 通常指当前容器，不能直接表示数据库容器或宿主机。
- [ ] 本地 Java 访问容器
  - 使用宿主机发布的地址和端口配置 JDBC、Redis 或消息客户端。
- [ ] Java 容器访问依赖容器
  - 在同一网络中使用服务名和依赖服务的容器端口。
- [ ] Compose 服务发现
  - 理解服务名解析与容器重建后的地址变化，避免固定依赖动态容器 IP。
- [ ] 容器访问宿主机
  - 区分 Docker Desktop 与 Linux Engine 的访问方式和额外配置要求。
- [ ] 应用监听地址
  - 检查 server.address 等配置，避免应用只监听容器内部的回环地址。
- [ ] 网络成员与隔离
  - 确认需要通信的容器加入正确网络，按需要隔离不同服务。
- [ ] 端口冲突与对外暴露范围
  - 检查宿主机端口占用和绑定地址，区分本机访问与外部访问。

## 六、数据持久化与文件挂载【P0：高频】

- [ ] 容器可写层
  - 理解容器内文件可以修改，但删除容器通常会丢失该层数据。
- [ ] 命名卷
  - 使用 Docker 管理的卷保存数据库等持久化数据。
- [ ] Bind mount
  - 将宿主机文件或目录挂载到容器，适用于配置、开发文件和指定数据目录。
- [ ] 卷与目录挂载的区别
  - 根据数据管理方式、路径依赖和访问需求选择挂载类型。
- [ ] 挂载路径
  - 区分宿主机来源路径与容器目标路径，检查文件和目录类型。
- [ ] 挂载覆盖
  - 理解挂载会遮蔽目标目录中已有内容，避免覆盖 JAR 或关键配置。
- [ ] 只读挂载
  - 为无需修改的配置和证书设置只读访问。
- [ ] 文件权限与用户身份
  - 检查容器用户、UID/GID 和宿主机目录权限之间的关系。
- [ ] 数据库目录
  - 按数据库镜像及版本要求挂载正确位置，避免错误迁移数据目录。
- [ ] Java 上传与导出文件
  - 将需长期保存的业务文件放到持久化存储或外部对象存储。
- [ ] 临时文件与 tmpfs
  - 区分临时存储与持久存储，考虑内存占用和容器重建后的行为。
- [ ] 删除容器与删除卷
  - 理解两者是独立操作，检查 Compose 移除卷选项的影响范围。

## 七、Spring Boot 外部配置与 JVM 参数【P0：高频】

- [ ] 同一镜像运行多个环境
  - 将环境差异放到运行配置中，减少为每个环境重新制作应用镜像。
- [ ] 环境变量配置
  - 使用 SPRING_PROFILES_ACTIVE 等变量提供 Spring Boot 配置。
- [ ] 数据源与中间件配置
  - 注入数据库、Redis 和消息服务地址，匹配实际网络位置。
- [ ] Profile 选择
  - 按项目约定启用开发、测试或生产配置，确认实际生效环境。
- [ ] 外置配置文件
  - 挂载配置文件，并理解默认查找位置、location 与 additional-location。
- [ ] 配置优先级
  - 区分配置文件、环境变量、系统属性和应用参数之间的覆盖关系。
- [ ] Compose .env 与容器环境
  - 理解 .env 主要用于 Compose 插值，变量不会仅因写入文件就自动进入容器。
- [ ] environment 与 env_file
  - 使用明确的方式向容器注入变量，检查不同来源的优先级。
- [ ] JVM 参数与应用参数
  - 区分堆大小、-D 系统属性和 Spring Boot 的命令行属性。
- [ ] JAVA_TOOL_OPTIONS 与 JAVA_OPTS
  - 区分 JVM 可读取的标准入口与需要启动脚本主动使用的变量约定。
- [ ] JSON 启动形式与变量展开
  - 理解 exec 形式不会自动执行 Shell 变量替换。
- [ ] 密钥文件与配置树
  - 在需要时使用挂载文件及 configtree 读取敏感配置，确认访问权限。
