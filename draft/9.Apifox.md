## 一、接口请求与基础操作【P0：最高频】

- [ ] Apifox 的定位
  - 理解 Apifox 在接口设计、文档、调试、Mock 和自动化测试中的作用。
- [ ] 团队、项目与目录
  - 理解团队容纳项目、项目组织接口，以及目录和模块的使用方式。
- [ ] 查找接口
  - 使用名称、路径、目录和标签快速定位需要调试的接口。
- [ ] 发送已有接口请求
  - 选择环境、填写参数并发送请求，查看服务端响应。
- [ ] 快捷请求
  - 在没有现成接口定义时，直接填写请求信息进行临时调试。
- [ ] HTTP 请求方法
  - 正确使用 GET、POST、PUT、PATCH、DELETE，理解它们与后端接口映射的关系。
- [ ] URL 与接口路径
  - 区分完整 URL、前置 URL 和接口路径，检查最终请求地址。
- [ ] 文档模式与调试模式
  - 区分以接口定义为中心和以请求调试为中心的工作方式。
- [ ] 请求保存方式
  - 区分暂存、保存为接口、保存为调试用例和请求历史。

## 二、请求参数与请求体【P0：最高频】

- [ ] Query 参数
  - 填写查询条件、分页和排序参数，对应 Spring 中常见的 @RequestParam。
- [ ] Path 参数
  - 填写 /users/{id} 等路径参数，对应 Spring 中的 @PathVariable。
- [ ] Header 参数
  - 设置 Authorization、Content-Type、租户标识和自定义请求头。
- [ ] JSON 请求体
  - 正确填写对象、数组和嵌套结构，对应 Spring 中常见的 @RequestBody。
- [ ] 参数启用与禁用
  - 使用参数复选框控制是否发送某个字段，区分不发送与发送空值。
- [ ] 字段类型与空值
  - 区分字符串、数字、布尔值、null、空字符串和空数组。
- [ ] Content-Type
  - 匹配请求体格式，区分 JSON、表单和文件上传等内容类型。
- [ ] form-data 与文件上传
  - 发送 multipart/form-data，区分文本字段和文件字段，对应 MultipartFile 等参数。
- [ ] x-www-form-urlencoded
  - 发送表单编码数据，区分它与 JSON 请求体。
- [ ] Raw 与 Binary
  - 根据接口要求发送纯文本、XML 或原始二进制内容。
- [ ] 参数编码与集合格式
  - 处理中文、特殊字符、重复参数和数组参数，确认服务端实际接收到的形式。

## 三、多环境与变量管理【P0：最高频】

- [ ] 本地、开发与测试环境
  - 为不同部署环境配置独立地址和变量，减少手动修改。
- [ ] 前置 URL
  - 将服务地址放到环境中，接口定义保留业务路径。
- [ ] 多服务地址
  - 为涉及多个后端服务的项目配置对应地址，确认接口使用哪个服务。
- [ ] 环境切换
  - 理解切换环境如何改变请求地址、变量值和附加参数。
- [ ] 环境变量
  - 保存随环境变化的 Token、账号、租户 ID 和测试数据。
- [ ] 变量引用
  - 使用 {{变量名}} 在 URL、Header、参数和请求体中复用数据。
- [ ] 本地值与远程值
  - 区分个人调试使用的值与团队共享的值，确认不同执行方式的取值来源。
- [ ] 全局、模块与临时变量
  - 根据复用范围和生命周期选择变量，避免所有数据都放进全局变量。
- [ ] 变量优先级
  - 理解临时、测试数据、环境、模块、项目全局和团队全局变量之间的覆盖关系。
- [ ] 变量类型处理
  - 理解变量存储与替换方式，正确处理数字、对象、数组及 JSON 引号。
- [ ] 公共参数与环境附加参数
  - 复用公共 Header、Query 等参数，检查继承、覆盖和重复发送问题。

## 四、登录、Token 与常见鉴权【P0：高频】

- [ ] 调用登录接口
  - 使用测试账号获取登录凭证，确认响应中 Token 的实际位置。
- [ ] Bearer Token
  - 在 Auth 中配置令牌，理解生成的 Authorization: Bearer 请求头。
- [ ] Token 变量化
  - 使用变量引用 Token，避免在每个接口中重复粘贴。
- [ ] 自动提取 Token
  - 在登录接口的后置操作中提取凭证，供后续接口复用。
- [ ] 目录鉴权继承
  - 在目录中统一配置鉴权，再为个别接口设置覆盖规则。
- [ ] 接口独立鉴权
  - 为登录、公开接口或特殊权限接口配置独立的认证方式。
- [ ] Cookie 与 Session
  - 查看、保存和发送 Cookie，理解基于会话的登录状态。
- [ ] Token 过期与账号切换
  - 更新凭证、清理旧登录态，避免使用错误账号测试权限。
- [ ] API Key 与 Basic Auth
  - 按接口要求配置密钥或用户名密码，确认凭证发送位置。
- [ ] 认证失败与授权失败
  - 结合 401、403 和业务响应区分未登录、凭证无效与权限不足。

## 五、响应查看与日常问题排查【P0：高频】

- [ ] HTTP 状态码
  - 根据 2xx、3xx、4xx、5xx 初步判断请求结果。
- [ ] HTTP 状态与业务状态
  - 区分 HTTP 请求成功与 code 等业务字段表示的处理成功。
- [ ] 响应 Body
  - 查看 JSON、文本、HTML、XML、二进制等不同响应格式。
- [ ] 响应 Header 与 Cookie
  - 检查内容类型、缓存、重定向、文件信息和登录状态。
- [ ] 实际请求
  - 查看变量替换后真正发送的 URL、Header 和 Body。
- [ ] 响应时间与大小
  - 观察耗时和数据量，区分单次请求观察与正式性能测试。
- [ ] 控制台与脚本日志
  - 根据错误提示和日志定位请求组装、脚本及网络问题。
- [ ] 响应结构校验
  - 检查返回字段、类型、必填项和约束是否符合接口定义。
- [ ] 额外字段与可空字段
  - 理解响应校验中允许额外字段、字段缺失和字段为 null 的区别。
- [ ] 常见参数错误
  - 排查 400、404、405、415 等问题对应的路径、方法、类型和内容格式。
- [ ] 与前端请求对照
  - 比较浏览器和 Apifox 的实际请求，定位 Header、Cookie、参数和编码差异。
- [ ] 联动后端排查
  - 结合 Spring Boot 日志、断点和请求标识，确认请求到达位置与执行结果。

## 六、接口设计与文档维护【P0：高频】

- [ ] 接口基本信息
  - 定义接口名称、方法、路径、说明和所属目录。
- [ ] 参数定义
  - 写清参数名称、位置、类型、必填性、说明和示例。
- [ ] 数据结构
  - 定义请求和响应中的对象、数组、嵌套字段及约束。
- [ ] 数据模型复用
  - 复用用户、订单、分页等模型，减少重复定义和不一致。
- [ ] 响应定义
  - 分别描述成功、校验失败、未授权和业务异常等响应。
- [ ] 响应组件
  - 复用统一响应结构，维护多个接口共同使用的返回约定。
- [ ] 请求与响应示例
  - 提供有业务含义的示例，区分示例数据与字段约束。
- [ ] 从响应生成结构
  - 利用实际响应辅助生成定义，再人工确认类型、必填和可空规则。
- [ ] 接口状态与负责人
  - 标记开发、测试、发布和废弃等状态，明确维护责任。
- [ ] 文档与实现一致性
  - 根据实际接口行为更新文档，避免临时调试修改被误写成正式契约。
- [ ] Markdown 补充说明
  - 记录业务规则、错误码、调用顺序、幂等要求和特殊限制。

  - 从历史请求恢复参数、重新发送或保存为接口用例。
- [ ] 分享请求结果

- [ ] 调试用例与测试用例
  - 区分方便手动调试的用例与用于自动化验证的测试用例。
- [ ] 用例同步规则
  - 理解接口定义变化对调试用例、测试用例和场景步骤的不同影响。

## 十、前后置操作与基础脚本【P1：经常使用】

- [ ] 前置操作
  - 在发送请求前准备变量、时间戳、签名和测试数据。
- [ ] 后置操作
  - 在收到响应后提取数据、执行断言并更新变量。
- [ ] JSONPath 与 XPath
  - 根据响应格式提取 Token、订单 ID 和其他业务字段。
- [ ] 接口之间传递数据
  - 将上一个接口的输出作为后续接口输入，形成可复用调用流程。
- [ ] 可视化断言
  - 校验状态码、字段值和响应内容，明确判断成功的条件。
- [ ] JavaScript 脚本
  - 理解脚本执行环境，使用简短脚本完成可视化操作无法表达的逻辑。
- [ ] pm API
  - 使用相应 API 读取请求、响应和变量，并设置后续请求需要的数据。
- [ ] 脚本断言
  - 使用 pm.test 等能力组织断言，定位失败的具体条件。
- [ ] 操作继承与执行顺序
  - 理解项目、目录、接口和用例中的公共操作如何继承和执行。
- [ ] 动态值与公共逻辑
  - 生成时间、随机数据和唯一标识，复用公共脚本减少重复。
- [ ] 脚本调试与兼容性
  - 使用日志检查变量和响应，不假定所有 Postman API 都完全兼容。

## 十一、Mock 与前后端并行开发【P1：经常使用】

- [ ] Mock 的作用
  - 在真实接口尚未完成或不便调用时，提供符合约定的模拟响应。
- [ ] 智能 Mock
  - 根据字段定义和规则生成数据，检查生成结果是否符合业务含义。
- [ ] 固定响应示例
  - 使用稳定数据复现指定页面和业务状态。
- [ ] Mock 期望
  - 根据请求条件返回指定响应，模拟不同业务分支。
- [ ] 正常与异常数据
  - 覆盖成功、空列表、缺失字段、权限失败和业务错误等情况。
- [ ] 本地与云端 Mock
  - 区分服务运行位置、可访问范围和数据配置方式。
- [ ] Mock 匹配与优先级
  - 排查多个规则同时满足时的返回选择。
- [ ] Mock 脚本
  - 使用专用脚本生成动态响应，区分它与请求前后置脚本的执行环境。
- [ ] Mock 变量边界
  - 确认 Mock 支持的数据来源，不直接套用调试环境中的变量使用方式。
- [ ] Mock 切换到真实接口
  - 保持契约一致并切换环境，再验证真实认证、持久化和异常行为。

## 十二、自动化测试与回归验证【P1：经常使用】

- [ ] 单接口测试用例
  - 为一个接口配置输入、断言和前后置操作，重复验证固定条件。
- [ ] 测试场景
  - 按业务顺序组合多个步骤，例如登录、创建订单、查询订单和取消订单。
- [ ] 测试套件
  - 将相关用例和场景组合运行，按模块或发布范围组织回归。
- [ ] 接口引用与复制
  - 理解测试步骤与原接口的关联及同步方式，避免接口变更后测试失真。
- [ ] 步骤间数据传递
  - 引用前置步骤结果，理解单独运行后续步骤时可能缺少上下文。
- [ ] 业务结果断言
  - 同时验证 HTTP、业务状态和关键字段，不只判断状态码为 200。
- [ ] 参数与权限覆盖
  - 测试必填缺失、边界值、非法值、未登录和权限不足等条件。
- [ ] 条件、循环与等待
  - 使用分支、循环和等待组织流程，避免无意义或无限的重复请求。
- [ ] 测试隔离
  - 为不同执行创建独立数据，减少共享账号、ID 和变量造成的干扰。
- [ ] 失败处理策略
  - 明确步骤失败后停止、跳过还是继续，防止连锁失败掩盖原因。
- [ ] 测试报告
  - 查看失败步骤、断言和请求信息，区分接口错误与测试配置错误。

- [ ] 定时任务
  - 按团队需要安排周期回归，并设计失败通知与结果处理。
- [ ] 访问令牌管理
  - 使用执行环境提供的凭证管理方式，按权限和生命周期维护令牌。

## 十六、专项鉴权、签名与其他协议【P2：按技术栈需要】

- [ ] OAuth 2.0
  - 按服务要求配置授权流程、Scope、回调地址和 Token 刷新。
- [ ] JWT 调试
  - 区分携带已有 JWT 与生成测试 JWT，确认算法、密钥和服务端规则。
- [ ] 请求签名
  - 在前置脚本中按服务约定处理时间戳、Nonce、排序和签名内容。
- [ ] 加密与解密
  - 按接口约定处理请求和响应，确认编码、算法和密钥来源。
- [ ] 其他认证方式
  - 在需要时配置 Digest、AWS Signature、NTLM 等认证，不混用不同协议。
- [ ] SSE
  - 查看持续推送的事件，检查事件内容、结束行为和连接异常。
- [ ] WebSocket 与 Socket.IO
  - 调试连接和双向消息，理解两者协议及客户端行为的区别。
- [ ] gRPC
  - 导入 Proto 并调试方法、Metadata、TLS 和流式调用。
- [ ] Dubbo
  - 按支持的接入方式配置服务、方法和参数，核对协议及版本要求。
- [ ] GraphQL
  - 配置 Query、Mutation、变量和鉴权，理解响应中的 data 与 errors。
- [ ] SOAP / WebService
  - 按服务定义发送 XML 请求，检查命名空间、操作和响应。
- [ ] Webhook
  - 使用相应调试能力接收并检查回调，验证事件内容和服务端确认行为。
- [ ] TCP / Socket
  - 按项目协议调试原始消息，并理解消息边界与粘包、分包问题。

## 十七、性能测试【P3：专项使用】

- [ ] 性能测试与功能测试
  - 区分正确性验证与负载下的吞吐量、延迟和稳定性验证。
- [ ] 选择压测场景
  - 根据业务选取单接口或完整链路，明确测试目标。
- [ ] 虚拟用户与运行时间
  - 配置并发负载、持续时间和爬坡过程，区分虚拟用户数与请求速率。
- [ ] 压测数据隔离
  - 准备可并发使用的数据，避免共享变量和账号造成错误结果。
- [ ] 性能指标
  - 观察请求量、吞吐量、响应时间分布、错误率和成功率。
- [ ] 执行机与服务端监控
  - 区分压测端瓶颈与服务端瓶颈，结合 CPU、内存、GC 和数据库指标分析。
- [ ] 结果对比
  - 固定负载、数据和环境，对比优化前后的表现。
- [ ] 工具能力范围
  - 确认当前版本的并发上限、报告与请求详情能力，必要时使用专门压测工具。
