## 二、RocketMQ 核心架构

- [x] Producer（生产者）
  - 负责创建消息并发送到 RocketMQ。
- [x] Consumer（消费者）
  - 负责接收消息并执行业务处理。
- [x] NameServer（名称服务）
  - 提供 Broker 注册与路由发现能力。
- [x] Broker（消息服务器）
  - 负责消息接收、存储、投递和消费进度管理。
- [x] Proxy（代理服务）
  - 理解 RocketMQ 5.x gRPC 客户端的接入方式及代理职责。
- [x] 集群架构
  - 理解多个 NameServer、Broker 和客户端如何协同工作。
- [x] 客户端版本与协议
  - 区分传统 Remoting SDK 与 5.x gRPC SDK，理解服务端版本和客户端 API 的关系。

## 三、RocketMQ 核心概念

- [x] Topic（主题）
  - 按业务类型组织消息，例如订单主题、支付主题。
- [x] Message（消息）
  - 理解消息体、属性及消息标识的组成。
- [x] MessageQueue（消息队列）
  - 理解 Topic 内部队列与并行处理、顺序保证之间的关系。
- [x] Consumer Group（消费者组）
  - 理解消费者组在负载均衡、订阅和消费进度管理中的作用。
- [x] Producer Group（生产者组）
  - 了解传统客户端中的生产者组，以及它与事务消息等功能的关系。
- [x] Tag（标签）
  - 使用标签对同一 Topic 下的消息进行分类和过滤。
- [x] Keys（业务关键字）
  - 使用订单号等业务标识辅助消息查询与问题排查。
- [ ] Message ID（消息标识）
  - 区分消息标识与业务唯一标识，理解重试时的去重依据。
- [ ] Offset（偏移量）
  - 理解队列位置和消费进度，掌握消息回溯的基础。

## 四、RocketMQ 工作流程

- [ ] 生产者启动
  - 初始化客户端，获取路由信息并建立连接。
- [ ] 创建消息
  - 设置 Topic、消息体、Tag、Keys 和业务属性。
- [ ] 发送消息
  - 客户端选择目标 Broker，并根据发送方式处理结果。
- [ ] Broker 存储消息
  - 理解消息接收、持久化和可消费之间的关系。
- [ ] 消费者订阅消息
  - 按消费者组、Topic 和过滤条件建立订阅。
- [ ] 消费者处理消息
  - 执行业务逻辑并反馈消费结果。
- [ ] 更新消费进度
  - 理解成功确认、消费进度推进和失败重试。

## 十二、RocketMQ 常见问题

- [ ] 消息发送成功是否代表业务成功
  - 区分发送成功、消息持久化、消费成功和业务完成。
- [ ] 为什么消息会重复消费
  - 理解重试和故障恢复机制，明确业务幂等的必要性。
- [ ] RocketMQ 是否保证全局顺序
  - 理解顺序保证范围，避免将局部有序理解为所有消息全局有序。
- [ ] 事务消息是否等于分布式事务
  - 理解其主要保障本地事务与消息生产的最终一致性，消费端仍需独立设计。
- [ ] 消费者为什么收不到消息
  - 排查订阅、过滤条件、消费者组、消费位置、网络和消息类型。
- [ ] 消息积压如何处理
  - 分析消费耗时、并发能力、资源瓶颈和下游限制。
- [ ] 增加消费者为什么没有明显提速
  - 理解消费模式、分配粒度和业务瓶颈对扩容效果的影响。
- [ ] 消息回溯是否会重复执行业务
  - 理解重新消费的影响，并通过幂等与操作范围控制风险。
- [ ] 延时消息是否能保证精确执行时间
  - 区分消息到期可见时间与消费者实际完成业务的时间。
