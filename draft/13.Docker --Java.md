## 一、Docker 基础与容器日常操作【P0：最高频】

- [ ] Docker 的作用
  - 理解 Docker 如何统一运行环境、隔离服务并简化部署。
- [ ] 镜像与容器
  - 区分镜像模板和运行实例，理解同一个镜像可以创建多个容器。
- [ ] Docker 客户端与 Engine
  - 理解客户端将操作发送给 Docker Engine，确认容器实际运行在哪台机器。
- [ ] 镜像仓库
  - 理解镜像从哪里下载，以及本地镜像、远程仓库和运行容器之间的关系。
- [ ] 查看容器
  - 查看运行中和已停止的容器，识别名称、ID、状态、镜像和端口映射。
- [ ] 创建与启动
  - 区分创建新容器与启动已有容器，避免重复创建同一个服务。
- [ ] 前台与后台运行
  - 理解后台运行只是改变终端连接方式，容器仍依赖主进程存活。
- [ ] 停止与重启
  - 区分正常停止、强制终止和重启，理解它们对 Java 进程的影响。
- [ ] 删除与重建
  - 理解删除容器与删除镜像、数据卷的区别。
- [ ] 容器命名
  - 使用清晰名称管理服务，处理名称重复和遗留容器。
- [ ] 常见运行参数
  - 理解名称、后台、端口、环境变量、挂载、网络和自动删除等参数的用途。
- [ ] 容器主进程
  - 理解 Spring Boot 的 Java 进程退出后，容器通常也会停止。

- [ ] 容器内执行操作

## 十五、CI/CD 与自动化交付【P2：按项目需要】

## 十七、容器安全与权限【P2：企业项目需要】

- [ ] 镜像来源
  - 使用团队认可的来源，核对维护情况、版本和运行平台。
- [ ] 非 root 用户
  - 让应用使用必要权限运行，并配置可写目录。
- [ ] 凭证与镜像层
  - 不将密码、令牌和私钥写入镜像，理解后续删除不一定移除历史层中的内容。
- [ ] 运行期凭证
  - 按平台能力提供 Secrets 或外部凭证，限制共享与可见范围。
- [ ] Docker Socket
  - 理解访问 Docker API 可能带来的宿主机控制能力。
- [ ] 特权与 Capabilities
  - 按真实需要配置权限，不把 privileged 当作通用故障解决方式。
- [ ] 只读文件系统
  - 在合适场景下限制根文件系统写入，同时提供临时和业务目录。
- [ ] 网络与端口范围
  - 只发布需要外部访问的入口，将内部服务放在适当网络中。
- [ ] 基础镜像更新
  - 对系统和 Java 运行时更新重新构建并验证应用。
- [ ] 构建依赖与供应链
  - 在需要时记录 SBOM、来源和签名，支持依赖追踪与产物验证。
