## 1. 事务消息与数据库事务的关系

反复追问的问题包括：

- 为什么要先发送半消息？
- 数据库事务提交后，生产者崩溃了怎么办？
- MQ 回查的是谁？由谁查询数据库？
- MySQL 到底保存了哪些事务信息？

**需要理清的核心：** Broker、生产者实例和数据库分别保存什么；数据库提交后生产者崩溃时，其他实例如何依据持久化的业务数据回应事务回查。

## 2. Topic、Broker、消息队列的层级关系

反复追问的问题包括：

- Broker 是不是一条消息队列？
- 两个 Broker 都有同名 Topic 时，消息发到哪里？
- 一个 Broker 下能否有多个属于同一 Topic 的队列？

**需要理清的核心：** Topic 是消息的逻辑分类；一个 Topic 可以有多个队列，这些队列可以分布在不同 Broker 上。生产者每次发送消息时，会选择其中一个队列。

## 3. 队列、消费者组、线程与消费进度

反复追问的问题包括：

- 一条队列能否由多个线程处理？
- 同一消费者组内的实例如何分担队列？
- 两个消费者组消费速度不同，快的需要等慢的吗？
- 前面有其他 Tag 的消息，会不会堵住后面的消息？

**需要理清的核心：** 区分「队列分配给哪个消费实例」「实例用哪些线程处理消息」和「每个消费者组消费到了哪里」。它们是三个不同的问题。

## 4. 客户端接入方式与代码配置

反复追问的问题包括：

- 客户端为什么需要 NameServer 或 Proxy？
- 传统 Remoting SDK、5.x gRPC SDK 和 `RocketMQTemplate` 有什么区别？
- 声明生产者使用某个 Topic，和发送消息时指定 Topic 有什么区别？

**需要理清的核心：** 客户端采用哪种 SDK 和协议，决定它配置的是 NameServer 地址还是 Proxy 地址，以及代码中使用哪套发送 API。
